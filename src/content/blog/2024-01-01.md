## ¿Qué es la inyección de dependencias? 💉

La inyección de dependencias es un patrón de diseño que se utiliza para crear objetos dependientes de otros objetos. En lugar de crear los objetos dependientes dentro de la clase que los utiliza, se los pasamos a través de un constructor o un método.

## ¿Qué es un contenedor de inyección de dependencias? 📦

Un contenedor de inyección de dependencias es un componente de nuestra aplicación que sabe cómo crear e inyectar dependencias. El contenedor de inyección de dependencias es responsable de instanciar clases, resolver sus dependencias y proporcionar una instancia de la clase cuando se le solicite.

### Ventajas 👌

- Reduce el acoplamiento entre clases.
- Facilita la reutilización del código.
- Facilita la prueba unitaria.
- Facilita la creación de objetos.
- Facilita la configuración de la aplicación.
- Optimiza el rendimiento de la aplicación.

En resumen, el uso de inyección de dependencias y particularmente utilizar un contenedor de inyección de dependencias nos permite crear aplicaciones más flexibles, mantenibles y testables.

### Desventajas 👎

- Aumenta la complejidad de la aplicación.
- Aumenta la curva de aprendizaje.

## ¿Cómo implementar un contenedor de inyección de dependencias en frontend? 🤔

En frontend tenemos muchas opciones para implementar un contenedor de inyección de dependencias, en este post vamos a ver como implementarlo en una aplicación React y Typescript, pero puedes implementarlo en cualquier framework o librería frontend.

Para esta ocasión utilizaremos [ts-injecty](https://github.com/damianpumar/ts-injecty) un contenedor de inyección de dependencias que yo mismo he creado, pero puedes utilizar cualquier otro contenedor de inyección de dependencias.

### Ventajas de ts-injecty 👌

- Zero dependencies.
- Javascript and Typescript support.
- Lightweight.
- No configuration (no reflect-metadata, ni configuraciones extras en tsconfig).
- Open source.

### Instalación 📦

```bash
npm install ts-injecty --save
```

### Índice 📖

#### Instanciar objetos sin dependencias

```ts
class A {
  public sum(x: number, y: number) {
    return x + y;
  }
}

const dependencies = [register(A).build()];

Container.register(dependencies);

const a = Container.resolve(A);

expect(a.sum(1, 2)).toBe(3);
```

#### Instanciar objetos con dependencias

Como podemos inyectar dinámicamente un objeto que depende de otro objeto, en este caso `A` depende de `B`.
Con `ts-injecty` podemos hacerlo de la siguiente manera, super simple 👇.

```ts
class A {
  constructor(private b: B) {}

  public sum(x: number, y: number) {
    return this.b.sum(x, y);
  }
}

class B {
  public sum(x: number, y: number) {
    return x + y;
  }
}

Container.register([register(A).withDependency(B).build()]);

const resolved = Container.resolve(ClassWithInterfaceDependency);

expect(resolved.doSomething()).toBe("HI");
```

#### Instanciar objetos con dependencias de dependencias

En este caso `A` depende de `B` y `B` depende de `C`, como podemos inyectar dinámicamente un objeto que depende de otro objeto que a su vez depende de otro objeto, facilísimo 👇.

```ts
class A {
  constructor(private b: B) {}

  public sum(x: number, y: number) {
    return this.b.sum(x, y);
  }
}

class B {
  constructor(private c: C) {}

  public sum(x: number, y: number) {
    return this.c.sum(x, y);
  }
}

class C {
  public sum(x: number, y: number) {
    return x + y;
  }
}

const dependencies = [
  register(B).withDependency(C).build(),
  register(A).withDependency(B).build(),
];

Container.register(dependencies);

const a = Container.resolve(A);

expect(a.sum(1, 2)).toBe(3);
```

#### Instanciar objetos con más de una dependencia

En este caso `A` depende de `B` y `C`, veamoslo 👇.

```ts
class A {
  constructor(
    private b: B,
    private c: C
  ) {}

  public sum(x: number, y: number) {
    return this.b.sum(x, y) + this.c.sum(x, y);
  }
}

class B {
  public sum(x: number, y: number) {
    return x + y;
  }
}

class C {
  public sum(x: number, y: number) {
    return x + y;
  }
}

const dependencies = [register(A).withDependencies(B, C).build()];

Container.register(dependencies);

const a = Container.resolve(A);

expect(a.sum(1, 2)).toBe(6);
```

> Como puedes observar, [ts-injecty](https://github.com/damianpumar/ts-injecty) ha cambiado el método `withDependency` a `withDependencies` en plural, esto es porque ahora podemos inyectar más de una dependencia. `ts-injecty` es lo suficientemente inteligente como para saber que si le pasamos un solo argumento a `withDependencies` es porque queremos inyectar una sola dependencia, y si le pasamos más de un argumento es porque queremos inyectar más de una dependencia. A demás este método nos mostrará en el intellisense el tipo de argumento que necesitamos pasar aplicando [type-checking](https://www.geeksforgeeks.org/type-checking-in-compiler-design/) en tiempo de compilación.

#### Instanciar objectos con una dependencia singleton

`ts-injecty` por defecto registra las dependencias como `transient` excepto que registremos una implementación (veremos más adelante).

Veamos el caso donde `A` depende de `B` y `B` es una dependencia singleton 👇.

```ts
class A {
  constructor(private b: B) {}

  public sum(x: number, y: number) {
    return this.b.sum(x, y);
  }
}

class B {
  public sum(x: number, y: number) {
    return x + y;
  }
}

const dependencies = [
  register(B).asSingleton().build(),
  register(A).withDependency(B).build(),
];

Container.register(dependencies);

const a = Container.resolve(A);

expect(a.sum(1, 2)).toBe(3);
```

#### Instanciar un objeto donde su dependencia es una interfaz

Cómo sabes, en `typescript` las interfaces no se transpilan, con lo cual este escenario es mucho más simple de lo que te imaginas, ya que no importa si la implementación de esa interfaz es una funcion, una clase o un hook de react, `ts-injecty` no tiene ningún problema en inyectar una dependencia de una interfaz, solo necesitamos que cumpla el contrato pactado en la interfaz.

Veamos una primera implementación de una interfaz 👇.

```ts
interface B {
  doSomething(): string;
}

class A {
  constructor(private b: B) {}

  public doSomething() {
    return this.b.doSomething();
  }
}

const Implementation = () => {
  return {
    doSomething(): string {
      return "HI";
    },
  };
};

Container.register([register(A).withDependency(Implementation).build()]);

const resolved = Container.resolve(A);

expect(resolved).toBeInstanceOf(A);
expect(resolved.doSomething()).toBe("HI");
```

También podríamos resolver este mismo caso, cuando tenemos una clase que implementa la interfaz, el resultado es el mismo, lo que cambia es la configuración de la dependencia.

```ts
interface B {
  doSomething(): string;
}

class A {
  constructor(private b: B) {}

  public doSomething() {
    return this.b.doSomething();
  }
}

class Implementation implements B {
  public doSomething(): string {
    return "HI";
  }
}

Container.register([register(A).withDependency(Implementation).build()]);

const resolved = Container.resolve(A);

expect(resolved).toBeInstanceOf(A);
expect(resolved.doSomething()).toBe("HI");
```

Me imagino que con todos estas alternativas, ya tienes una idea de como puedes implementar un contenedor de inyección de dependencias en tu proyecto frontend.

Ahora, ¿qué pasaría si necesitas cambiar tus dependencias en tiempo de ejecución? con `ts-injecty`es super simple la verdad, ya que solo tienes que crear una clase heredar esta clase a una `Factory` que viene implementado en `ts-injecty` y luego registrar esa clase como una dependencia, veamoslo 👇.

```ts
interface X {
  doSomething(): string;
}

class A {
  public doSomething() {
    return "HI";
  }
}

class B {
  public doSomething() {
    return "BYE";
  }
}

import { Factory } from "ts-injecty";

class FactoryImplementation extends Factory {
  public create(type: "A" | "B"): X {
    if (type === "A") {
      return this.resolver.resolve(A);
    }

    return this.resolver.resolve(B);
  }
}

Container.register([
  register(A).build(),
  register(B).build(),
  register(FactoryImplementation).build(),
]);

const resolved = Container.resolve(FactoryImplementation);

expect(resolved.create("A")).toBeInstanceOf(A);
expect(resolved.create("B")).toBeInstanceOf(B);
```

En este caso, `ts-injecty` inyectará automáticamente al instanciar esta `FactoryImplementation` un `Resolver` que nos permitirá resolver las dependencias que necesitemos en tiempo de ejecución.
